# Подготовка декомпиляций

Из корня репозитория, PowerShell 5.1 или новее:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ghidra/prepare.ps1 -GhidraHome '<Ghidra>' -JavaHome '<JDK>' -RunId s01-initial
```

Нужны установленная Ghidra и совместимая с ней JDK. Проверенная среда первого
запуска: Ghidra 12.1.2 PUBLIC, JDK 21.0.12.1+1, Windows x64.
Скрипт использует Java напрямую, без изменения глобальных настроек.
RunId должен быть новым: существующие исследования не перезаписываются.

Обрабатываются основные `SMUTA.EXE` и `Rd.EXE` из manifest. Формат,
архитектуру и compiler spec определяет loader Ghidra; автоанализ — стандартный,
не более двух CPU, декомпиляция — до 60 секунд на функцию. Ручные исправления
типов и границ функций не выполняются. Стандартный PE loader может читать
соседние и системные DLL для разрешения импортов; пути и сообщения остаются
в журналах. Эти DLL не импортируются в проект как отдельные программы.

Результаты:

- `research/ghidra/<RunId>/SmutaRD.gpr` — проект обеих игр для открытия в Ghidra.
- `decompiled/<RunId>/<игра>/all-functions.c` и `functions/*.c` — автоматический
  псевдокод всех обнаруженных внутренних функций, включая thunks.
- `functions.tsv` — адрес, имя, размер тела, статус, файл и диагностика каждой
  попытки; `summary.properties` — счётчики успехов и ошибок.
- `disassembly.tsv` — все распознанные инструкции с байтами и переходами;
  `symbols.tsv` — символы, включая внешние.
- `program.txt` — версия, SHA-256, loader, language/compiler spec, image base,
  блоки памяти, точки входа и параметры анализа.
- `research/evidence/decompilation/<RunId>/` — аргументы запуска, журналы,
  инвентаризации всех файлов `originals/` до и после, сводка `run.json`.

Полные результаты исключены из Git. Псевдокод не является собираемым исходным
кодом или проверенной реализацией; успешная декомпиляция не подтверждает
типы, соглашения вызова, полноту обнаружения функций и игровое поведение.
Предупреждения Ghidra сохраняются даже при успешном результате.

Независимая проверка сохранённого проекта:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File tools/ghidra/check.ps1 -RunId s01-initial
```

Она повторно открывает проект headless с `-process '*.EXE' -noanalysis -readOnly`
и `CheckResearch.java`, используя записанные Java и системные свойства.
Проверка сопоставляет SHA-256 и каждую сохранённую функцию с её непустым
файлом экспорта; доказательства — `*-reopened.txt` и маркеры
`SMUTARD_REOPEN_CHECK_PASSED` в журнале. Повторная проверка обновляет свой
журнал и доказательства, не изменяя проект и экспорт.

## Уточнённый псевдокод

После подготовки `s01-initial`:

```powershell
& tools/ghidra/refine-pseudocode.ps1
& tools/ghidra/refine-pseudocode.ps1 -Verify
node tools/research/verify-refinement.cjs
```

Первая команда создаёт отдельную копию проекта `s01-refined`, уточняет десять
функций и экспортирует только их. Вторая проверяет сохранённые модели повторным
открытием без изменений. Третья сверяет листинги с PE и проверяет устранение
потерянных входов/аргументов. Полный охват, адреса и сохраняющееся ограничение
декомпилятора x87 — в [отчёте](../../docs/pseudocode-refinement.md).
